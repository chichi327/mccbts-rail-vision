# 去畸变与供应商标定说明

给**标定供应商**和现场对接用。算法侧几何全部建立在本文描述的去畸变结果上。仓库内示例 `config/calib/cam01/`（`vendor: sample-not-for-production`）只能验证管道，**不能当现场精度。**

架构总览见 [system-design.md](../architecture/system-design.md) 第 7 节；目录文件名见 [configuration.md](configuration.md)。

---

## 1. 画面怎么走到算法

算法**不直连海康网页**。路径是：

1. 海康主码流（现场一般为 1920×1080）→ 同机 MediaMTX **透传、不转码**
2. 本服务用 OpenCV/FFmpeg 解成 **BGR 整帧**
3. 若解码尺寸与 `config/cameras.yaml` 的 `width`/`height` 不一致，会先 **resize 到该分辨率**（内参必须按这一分辨率标定，禁止「按 4K 标、算法按 1080p 跑」）
4. 用本路 `camera.npz` 的 `K`、`dist` **去畸变**（见第 2 节）
5. 检测、跟踪、到轨距离、障碍物高度都在这张**去畸变 BGR** 上算

因此：供应商在海康预览页、未去畸变原图、或另一种裁切上点的地面点，**不能**用来算单应 `H`。

## 2. 当前去畸变实现（请按此复现）

实现：`core/ingest/undistort.py`。针孔 + OpenCV 畸变模型（`cv2.initUndistortRectifyMap` / `cv2.remap`）。**不支持**鱼眼 `cv2.fisheye`、Kannala-Brandt 单独接口，除非事先书面改约定。

对每一路有效标定，启动后按「标定目录 + 帧宽 + 帧高」缓存一张映射表，之后每帧只做插值。

等价于下面这段（请供应商用**同一段**处理标定用的静图或视频帧，再在结果上点地面）：

```python
import cv2
import numpy as np

# K: 3×3，dist: 与 OpenCV 一致，常见 (5,) = k1,k2,p1,p2,k3；也可 4/8/12/14
# bgr: uint8，高×宽与标定时一致（现场主码流多为 1080×1920 之 高×宽）
h, w = bgr.shape[:2]
new_k, _roi = cv2.getOptimalNewCameraMatrix(K, dist, (w, h), 0)
map1, map2 = cv2.initUndistortRectifyMap(
    K, dist, None, new_k, (w, h), cv2.CV_16SC2
)
undist_bgr = cv2.remap(bgr, map1, map2, interpolation=cv2.INTER_LINEAR)
```

必须对齐的细节：

| 项 | 本服务取值 | 供应商若不一致的后果 |
|----|------------|----------------------|
| `alpha` | **0** | `alpha=1` 会保留全部源像素、边缘无效区不同，`H` 对不上 |
| 第二返回值 `roi` | **丢弃，不裁切** | 按 ROI 裁图后再标 `H`，像素坐标原点会偏 |
| 输出尺寸 | 与输入 **w×h 相同** | 黑边可以有，不要改分辨率 |
| 旋转/立体校正 `R` | **`None`（单位阵）** | 不要再乘额外的 stereo R |
| 插值 | `INTER_LINEAR` | 一般可忽略；标点请在本 remap 结果上做 |
| 颜色 | BGR，与 OpenCV 一致 | 不要在 JPEG 压缩后再当几何真值 |

`getOptimalNewCameraMatrix(..., alpha=0)`：去畸变图里有效像素尽量铺满，源图边缘可能被丢掉，四角可能出现黑边。单应必须在这张 **w×h 全图** 的像素坐标 `(u, v)` 上估计，原点仍是图像左上角。

## 3. 每路相机交付目录

路径：`config/calib/<camera_id>/`，其中 `<camera_id>` 与 `cameras.yaml` 的 `id`、MediaMTX 路径名一致（例如 `cam01`）。

五个文件**缺一不可**。缺文件或 `meta.yaml` 里 `undistorted` 不为 `true` 时：本路 `calib_invalid`，**跳过去畸变（原图进检测）**，距离和高度不上报。

### 3.1 `camera.npz`（去畸变必须）

| 键 | 形状 / 类型 | 说明 |
|----|-------------|------|
| `K` | 3×3 `float64` | 针孔内参，对应标定时宽高（与码流一致） |
| `dist` | 长度 4/5/8/12/14 的向量 | OpenCV `undistort` 畸变系数；现场常用 5 参数 |

标定板/点应在**与算法相同的主码流分辨率**下拍摄。变焦、换镜头后重交 `K`/`dist`。

### 3.2 `homography.npz`（测距必须）

| 键 | 形状 | 说明 |
|----|------|------|
| `H` | 3×3 | **去畸变图像素 → 地面坐标系（米）** |

本服务用法：地面点 = `H @ [u, v, 1]`，再除以第三维。`(u, v)` 是第 2 节 `undist_bgr` 上的像素（框的底边中心等）。

`H` 必须在第 2 节那张去畸变全图上，用轨面/地面已知点估计。禁止用海康网页、未去畸变图、裁切 ROI、或缩放后的图。

### 3.3 `rails.yaml`（到轨距离必须）

与 `H` **同一地面坐标系（米）**。当前算法：目标脚点/车底中心到**最近一段钢轨折线**的水平距离。

```yaml
rails:
  - id: left
    p0: [0.0, 0.0]      # 段起点 [x, y]，米
    p1: [0.0, 200.0]    # 段终点
  - id: right
    p0: [1.435, 0.0]
    p1: [1.435, 200.0]
```

可多段折线逼近曲线。标准轨距 1435mm 时，两轨在该坐标系下的横向间距应与现场一致（示例为 1.435m）。若工务要「到限界」而不是「到最近钢轨」，改轨几何或量测，不改检测器。

### 3.4 `extrinsics.npz`（测高必须）

当前加载：

| 键 | 要求 |
|----|------|
| `R` | 3×3，可选；缺省单位阵 |
| `t` | 长度 3，可选；缺省 0 |
| `height_m` | 标量；有则作为相机离地高度；否则用 `‖t‖` |

请同时提供 **`R`、`t`（相机到地面/轨面约定系）和 `height_m`**。姿态若只用欧拉角，请先转成 `R` 再交文件（本仓库**尚未**解析 `rpy_rad`）。

障碍物高度目前是单目粗估（去畸变框高 + 地面距离 + `K` 的 `fy`），精度以供应商书面承诺为准。

### 3.5 `meta.yaml`

| 字段 | 要求 |
|------|------|
| `width` / `height` | 与主码流、`cameras.yaml` 一致，现场多为 `1920` / `1080` |
| `undistorted` | 必须为 `true`（表示几何定义在去畸变图上，不是「相机已出无畸变码流」） |
| `date` | 标定日期 |
| `vendor` | 供应商名称 |
| `camera_serial` | 相机序列号或现场编号 |
| `error.distance_m` / `error.height_m` | 验收用误差范围（米）；未知可先填数字承诺，不要长期 `null` |

## 4. 供应商还需要做什么（交付清单）

请按相机逐路交付，并附一页书面说明：

1. **`K`、`dist`**：主码流分辨率下的针孔标定，模型与第 2 节 OpenCV 一致。  
2. **用第 2 节脚本生成去畸变图**，在其上采集地面控制点，估计 **`H`**。交出所用控制点像素与地面坐标，便于复查。  
3. **`rails.yaml`**：与 `H` 同一地面系；说明原点、X/Y 轴向（例如沿轨、垂直于轨）。  
4. **`R`、`t`、`height_m`**：测高用；书面确认单目高度能否验收、大概误差（米）。  
5. **`meta.yaml` 填全**，`error.*` 给出验收指标。  
6. **码流约定**：主码流分辨率、是否变焦、与 `cameras.yaml` 一致；禁止算法侧再缩放后再套这套 `K`。  
7. **重标条件**：挪机、撞击、换镜头、变焦后重新出全套文件。  
8. **不要**把海康官方网页、子码流、或 MediaMTX WebRTC 截图当作几何标定源。

联调建议：先交一路 `cam01` 全套 → 我方替换 `config/calib/cam01/` 后重启 → 在去畸变预览上核对轨面是否与 `rails` 投影大致重合 → 再谈误差验收。

## 5. 我方尚未做、但不挡「先按同一套图交标定」

| 项 | 说明 |
|----|------|
| GPU remap | 现为 CPU 缓存 remap，1080p 约 10ms 量级；不改变几何，只影响延迟 |
| 运行中 `calib_stale` | 设计里有「画面钢轨与标定轨偏差过大」告警，**尚未实现**；现场仍靠重标与抽检 |
| 自动校验 `K` 与帧尺寸 | 映射表按**实际帧宽高**建立；若码流分辨率与标定不一致，几何会错，需人工保证一致 |
| 鱼眼独立模型 | 未接；若镜头必须鱼眼，需另行书面改接口 |
| `rpy_rad` 欧拉角文件 | 未解析，请交 `R` |

## 6. 我方怎么确认文件被用上

启动后该路标定有效时，日志会出现 `undistort maps ready ... size=宽x高`。心跳 `calib_status=ok`。若 `calib_invalid`，去畸变被跳过，距离/高度不会对。

打开耗时埋点时，`undistort_ms` 反映的是 remap，不是「有没有按你的 `K` 做」；几何对错仍靠控制点与现场量尺。
